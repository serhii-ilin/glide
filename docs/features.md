# Glide requirements and feature registry

This file is the single record of what Glide must do (requirements, `R-xxx`) and what it
does or will do (features, `F-xxx`). Rules for keeping it current, including TDD and Gherkin
requirements, are in `AGENTS.md`.

Status: `planned` · `in-progress` · `done` · `partial` · `deferred` (with reason) · `removed`

## How to read this registry

- Every requirement has an ID, a testable statement, a `Source / basis` (standard,
  benchmark, or explicit product decision), the features that satisfy it, and a milestone.
  Acceptance is defined by the Gherkin scenarios linked from those features.
- Every feature has a `Description` of user-visible behavior, a `Gherkin` path to
  `tests/features/F-xxx-<slug>.feature`, and `Tests` that implement its scenarios.
- New or changed behavior follows TDD: edit the Gherkin scenario, write a failing test,
  then implement. `backfill pending` marks an existing feature whose script has not been
  written yet; it must be added in the next branch that changes that feature.
